# בנייה מקצה לקצה

ענת פותחת ריפו ב-GitHub ובוחרת פרויקט ב-Supabase. כל השאר עליי, בלי לעצור לשאלות שאפשר להכריע לבד. המטרה: כמה שפחות אינטראקציות, ואף פעם לא אותה הערה פעמיים.

## עקרונות

- תמיד בעברית. בלי אייקונים או סמלים, גם לא בכפתורים. חריגה קבועה אחת: מפתח מאיר ליד כפתור שמפעיל מפתח בתשלום.
- לא להעביר אליה צעדים, סיסמאות, מפתחות או הגדרות. התוצר הוא כתובת חיה ושורה אחת על מה השתנה.
- לשאול רק כשההחלטה בלתי הפיכה ואפשר לפרש אותה לשני כיוונים. אחרת להחליט, ולציין את ההנחה בשורה אחת.
- כל חריגה מהסקיל נאמרת מראש, לא בדיעבד.
- כשמשהו נחסם: לנסות כל דרך זמינה לפני שמדווחים. אם באמת אי אפשר, משפט אחד.
- לפני כל בנייה לקרוא את CLAUDE.md בריפו ואת "תיקונים קבועים" כאן.
- אחרי כל תיקון שלה: להוסיף אותו ל-CLAUDE.md של הריפו. אם התיקון כללי, להציע בסוף המסירה שורה אחת לעדכון הסקיל.
- כמה בקשות בהודעה אחת: כולן באותו סבב, PR אחד, מסירה אחת.

## תהליך

1. אפיון קצר בתוך התשובה: בעיה, משתמש, מסלול מרכזי, מידע נשמר, מוצר מינימלי. לא לחכות לאישור אם הבקשה ברורה.
2. מקור קיים (HTML או Lovable): לפצל לקבצים, לחלץ תמונות ל-public, לשמור תוכן ולוגיקה, ולהוסיף את שפת העיצוב מעל.
3. Supabase רק כשיש מידע לשמור. בפרויקט משותף: קידומת לכל טבלה, באקט ופונקציה, ולא נוגעים בשום דבר אחר. ברירת מחדל: בלי כניסה ובלי מערכת הרשאות. RLS פעיל, גישה ל-anon רק לטבלאות שלנו. כניסה ואדמין רק אם ענת מבקשת במפורש.
4. קוד: Vite + React + framer-motion (או Vite בלבד לאתר תוכן סטטי, ולומר מראש). עברית ו-RTL. הכתובת היא המצב (`#עמוד/פריט`).
5. רכיבים קבועים:
   - סרגל ניווט עליון קבוע בכל הדפים. חלונות העמקה נפתחים מתחתיו.
   - מימין: לוגו האפליקציה (אייקון בלי טקסט) ליד השם. השם מקשר לדף הבית: חזון, מטרה, דרך, מפת התוכן והדרכה.
   - משמאל: הלוגו של ענת (`public/logo.png`), כל המלבן הלבן כמו שהוא, עם ה-A והשם. לא לחתוך ולא להסיר רקע. הלוגו הוא כפתור ההגדרות.
   - כרטיס ההגדרות: העתקת קישור, שיחת הפיתוח, פרויקט המחקר, התקנת האפליקציה, ופרטי הפרויקט (ריפו, Supabase, שם המפתח ומיקומו, פונקציות, פריסה). אף פעם לא ערך של מפתח. אין שורת כפתורים בסרגל.
   - התקנה מ-Chrome: manifest, sw.js, אייקון. בכל שינוי בקבצים במטמון להעלות את `CACHE`.
   - בכל עמוד: "איך לקרוא", "תובנה" והקשר אדריכלי. הפרדה בין עובדה, מסורת והערכה.
6. בדיקות (ראו למטה).
7. GitHub: ענף עבודה, PR, ומיזוג מיד אחרי בדיקה ירוקה ו-preview במצב READY, בלי לשאול.
8. Vercel: `create_project` עם `gitRepository`, בלי `teamId`, `ssoProtection: null`. ייצור רק מ-main. משתני `VITE_` לפני הפריסה הראשונה.
9. אימות: פריסת main במצב READY (כלי Vercel), נתונים חוזרים מ-Supabase (SQL).
10. מסירה: כותרת שמבטאת את התובנה, כתובת, שורה על מה השתנה, נקודה עיוורת אחת אם יש, צעד הבא אחד. לעדכן CLAUDE.md.

## תיקונים קבועים של ענת

- תמונות שמסבירות את התוכן משותפות לכל המכשירים והמבקרים, לא לפי מכשיר.
- כל תוצאה של כלי באפליקציה (אבחון, ניתוח, חישוב) נשמרת בספרייה בדף שלו: תמונה, הסבר ותובנה, משותפת לכל המכשירים, עם כפתור שמחזיר אותה. בלי תמונה לא נשמרת. מהדפדפן: קריאה והוספה, בלי מחיקה.
- כלי עבודה תמיד גלויים (הדבקה, העתקה, שמירה). לא להסתיר מאחורי כניסה.
- כרטיסים מתהפכים: כל כרטיס עם מצב היפוך משלו. ריחוף במחשב, הקשה במגע.
- גרפיקת רקע חלשה מאוד (שקיפות כ-0.1), רק בצד עם מעט טקסט.
- לא לחזור על תוכן: ההסבר צמוד למקום שלו, לא ברשימה נפרדת.
- ריווח: מערכת אחת במשתנים (`--g`, `--g-sm`, `--g-lg`, `--pad`, `--block`). עמודות מתיישרות לגובה, ורכיב חזותי בגובה המסגרת שלידו.
- טיפוגרפיה: גוף 17px, h3 כ-1.22rem, h2 כ-1.75rem, h1 עד 2.8rem, כותרת ראשית עד 5rem. כותרות מודגשות בקו קצר מעליהן.
- צבע רק כשהוא נושא משמעות (קטגוריה, אלמנט, רמת התאמה מאדום לירוק).
- המחשות: פרומפט בעברית מהתוכן, מסתיים ב-`Documentary realism, Professional architecture photography, 1:1 --ar 1:1 --no text, words, writing, frame divisions`. בחזית שם, תובנה עד 15 מילים ותמונה. מאחור פרומפט, העתקה, הדבקה ושמירה משותפת.

## מפתחות ופעולות בתשלום

- מפתח API רק כסוד בשרת (Edge Function). לא בדפדפן, לא מוצג.
- ליד כל כפתור שמפעיל מפתח בתשלום: מפתח מאיר (SVG זהב עם זוהר, `KeyMark`).
- במסירה הראשונה של כפתור כזה: שורה אחת שמזכירה תקרת הוצאה בקונסולה של הספק.
- Claude API: `claude-sonnet-5-5` לראייה וניתוח, פלט JSON מובנה, סוד קיים `ANTHROPIC_API_KEY` אם יש.

## בדיקות

- קובץ הבדיקה בריפו (`tests/e2e.cjs`), מתעדכן בכל שינוי. בדיקות שכבר לא נכונות נמחקות.
- Playwright מול `vite preview`, מוקים לכל Supabase (rest, storage, functions) עם מאגר בזיכרון: שמירה, רענון, ומכשיר שני.
- כל כפתור, מחשב 1440 ונייד 390, בלי גלילה אופקית, בלי שגיאות קונסול, כל קריאה ממוקה. צילום מסך שמסתכלים עליו.

## מלכודות ידועות

- supabase.co ו-vercel.app לא נגישים מהסביבה: SQL, `extensions.http` לבדיקת פונקציה, כלי Vercel לפריסה.
- MCP של Supabase נתקע על DROP או REVOKE: `ALTER POLICY`, להוסיף במקום למחוק.
- פרויקט משותף: לפני ואחרי שינוי, ספירה ו-md5 של המדיניות שאינן שלנו.
- Edge Function עם `verify_jwt`: מפתח anon הישן (JWT).
- `git fetch origin main` לא תמיד מעדכן: `git fetch origin main:refs/remotes/origin/main`. אחרי מיזוג, ענף חדש מ-main.
- framer-motion בתוך SVG מזיז כ-transform: אלמנטים רגילים עם מעבר CSS.
- ייבוא מעגלי App ורכיבים: ניתוב בקובץ נפרד.
- heredoc: `<<'EOF'` עם מירכאות.
- גלילה אופקית ב-RTL: `minmax(0,1fr)` ו-`min-width:0`. motion בשורת flex: `flex: 0 0 auto`.
- grid עם `overflow:hidden` במיכל גלילה: `grid-auto-rows:max-content`.
- GitHub Pages חסום דרך API. קידום preview לייצור נכשל (422): מיזוג ל-main.
